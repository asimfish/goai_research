# 01_封面

答辩要点（不逐字念，按提示自然讲）：

- 我们是第13队科学无极，作品 SAGE-Mat。一句话：一行研究主题进去，可核验的综述、证据链和候选合成路线出来。
- 定位：一个通用的文献调研引擎，加上面向合成实验方案的特化——证据约束、接入训练好的前驱体预测模型、能从失败中迭代。
- 服务对象是自动化实验室：交付的方案可执行、结果可回写、下一轮更优。
- 右侧四个数字是规模与科学内容：约三千八百万篇本地全文加在线检索；九个角色四个自研服务；二十八条合成条件逐字段比较；七种化合物的前驱体预测与四个新实验方向。

答辩路线建议：三分钟讲 1、2、4、7、8、11、13 页；五分钟再加 3、6、9、12 页。

# 02_背景与科学gap

- 解决什么问题：自动化实验室不缺产能，缺的是"做什么实验、为什么做"——这一步仍靠人读文献。
- 空缺：让大模型把文献知识抽取、总结、压缩成可执行的假设，和实验结果、历史文献一起迭代。
- 强调闭环右下角：失败的实验同样回写为证据，Agent 据此给出下一轮更优方案——这是我们与"写一篇总结"的根本区别。
- 为什么现在：实验产能远大于知识吞吐；文献里的成功与失败边界是最便宜的实验。

# 03_科学问题

- 合成条件与前人经验散落在文献里，站在巨人肩膀上才有新发现：用哪些、怎么找、找到之后新发现在哪。
- 两个案例的问题来源不同：LLZO 是团队初赛自主探索定的，文献多但没人整理成跨掺杂体系的统一工艺图景；Ba5Y12Zn[O(SiO4)]8 是领域专家推荐的，2024 年首报、只有一篇直接合成文献，但近邻体系证据丰富。
- 一个文献丰富、一个文献稀缺，正好检验系统两端的能力。

# 04_系统能力

- 核心创新之一：把"生成像论文的结论"改成"保存证据与判定过程"。
- 认知层九个角色都是 Markdown 写的规程，Codex 执行——这是通用调研引擎；材料特化在确定性层：前驱体预测模型、近邻体系与相图两条强制检索面、合成条件表。
- 确定性工作进四个自研 MCP 服务；控制层每个阶段有完成标准，由程序检查，不由模型自己宣布；写稿与审稿分离。
- 九个角色编号与后面几页一一对应，评委可以对着看。

# 05_Agent交互与数据流

- 角色之间靠产物文件和共享进度记录交接：每一步是否通过、待返工问题、产物版本；上游一变下游自动重查。
- 写作与图纸、想法方案并行，审稿覆盖三者，问题沿原路返工。
- 底部是接到自动化实验室之后的样子：结构化路线 + 失败判据交给实验，结果按同一格式回写为证据，触发新一轮。

# 06_方法路线与闸门

- "做完了"不由模型说：九道关卡全部通过、没有未关闭的严重问题、终审有审稿记录，程序才放行。
- 正式运行里四次需要人确认的节点，其中一次是五条作者名不匹配的文献三轮没收敛，交人决定后删除继续——系统不会为了"好看"保留可疑引用。
- 对抗审稿用全新上下文、三个视角（领域专家、方法严谨派、期刊编辑）。

# 07_RECIPE融入

- 核心创新之二：把建模的反应前驱体预测接进 Agent 回环。RECIPE 把无机逆合成重述为变长前驱体集合的排序问题：高召回候选池 → 枚举二到五元集合 → 学习到的重排器直接给完整集合打分（团队 NeurIPS 2026 投稿）。
- 前驱体交给模型；温度、气氛、助熔剂不由模型臆造，从结构近邻的实验记录按证据等级类比，并标出不可迁移的边界。
- 左下角是随 checkpoint 提交的基准：两千五百五十八条留出反应，Combo@1 71.81，比先前最优基线高 11.4 个百分点。
- 每条路线都标注"模型候选、未经实验验证"。

# 08_正式案例结果

- 实际效果：纯主题冷启动，唯一输入是一行主题；先交出二十页综述，按材料专家八条意见修订为二十三页正式稿。
- 五十一篇参考文献逐条核对通过；正文二百一十九次引用；三张图由同一图源生成可编辑版本；两轮对抗审稿的终审零遗留。
- 右侧运行事实：整个过程都被记录，可以逐条回看。

# 09_科学结论与实验方向

- 系统给出的不是一份配方，而是文献证据限定的可迁移范围。
- 公开证据只能确认目标相的开放体系高温溶液法和单晶衍射鉴定；无锌谱系提供三类可比路线但数值不能无条件迁移；获得单晶不等于建立批量相纯窗口。
- 因此第一步实验是局部相图；四个方向每个都配了工艺路线和模型候选前驱体，成功与失败分别意味着什么都写清楚了。

# 10_LLZO案例

- 文献丰富的一端：四十六篇文献覆盖六个子主题、逐条核对通过，整合成十页综述。
- 模型首选前驱体路线（氧化锆、氧化镧、碳酸锂）与文献一致；次选出现可疑命名，恰好说明模型生成 → 化学式规范化 → 文献复核 → 对抗审稿这四步把关是必要的。
- 替代材料 Li6PS5Cl、Li3YCl6、LATP 的首选路线也过了文献复核，对应三种应用场景。

# 11_证据链与可追溯

- Demo 最能说明什么：这套系统是"在跑"的，不是一张流程图。演示用自研的「循证台」控制台。
- 演示顺序：输入一行主题发起 → 看到编排器定范围、派出文献检索和风格库两路并行 → 每个角色卡上是它正在做的动作、最近产出、用时 → 研究推进条显示当前阶段与负责角色 → 九项质量检查逐项亮起 → 审稿意见出现时标明责任角色和返工阶段 → 完成后打开综述 PDF、交付清单和可核验摘要；历史运行可以回放。
- 截图是答辩前正在运行的 LLZO 主题：文献检索阶段、六个角色并行。所有数据来自各角色的事件流、共享进度记录和工具调用审计，控制台只读不干预。

# 12_复现情况与限制

- 相比其他方案的特点：通用 Deep Research 类工具给出一段带引用的总结；我们做了四点不同。
- 一，引用零信任：只引检索到且逐条核对过的文献，查无此文直接删，正式案例 51/51。
- 二，前驱体由训练好的模型预测，条件从近邻体系按证据等级类比并标出不可迁移边界，而不是纯文本推理。
- 三，完成由程序判定：九项检查、写稿审稿分离、意见按角色返工；失败与返工记入进度记录，成为下一轮的证据。
- 四，全流程开源可复现：Codex 宿主 + 四个自研 MCP + 控制台，MIT；一键安装、冒烟一两分钟、同一主题可重跑。
- 诚实边界：目标相只有一篇直接报道；大模型步骤不能逐字复现，以关卡全部通过为判据；三个新主题的冷启动随包提交。

# 13_开源与结论

- 收尾回到定位：面向自动化实验室——方案可执行、结果可回写、从失败中迭代。
- 这套系统真正改变的，是把"该不该相信这条结论"变成一个可以点开 DOI 与原文段落回答的问题。
- 对研究者：一次运行替代数周文献梳理；对自动化实验室：交付结构化、可调度的方案，成功与失败的实验都回写为证据、Agent 据此迭代；对稀缺体系：只有一篇直接报道也能给出方向与前驱体候选，并明确哪些近邻条件不可迁移。
- 下一步：接入实验平台的结果回写，对四个方向开展合成实验，扩展温度 / 气氛条件预测。仓库 MIT 开源。
