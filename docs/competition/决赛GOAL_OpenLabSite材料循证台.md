## 3. 执行结构与状态职责

```mermaid
flowchart LR
    A[AI 实验方案及依据] --> B[版本化固定模板与参数校验]
    B --> C[循证台方案 / 工作流 / Three.js]
    C --> D[平台服务端 MCP 客户端]
    D --> E[UniLabOS 工作流调度]
    E --> F[新模拟设备驱动]
    F --> G[持久化轨迹命令桥]
    G --> H[Three.js 执行器]
    H -->|终态与完成回执| G
    G -->|校验并返回结果| F
    F -->|函数完成| E
    E -->|HTTP 状态读取 / SSE 通知| C
```

1. **方案与模板**：方案保存来源、研究 ID、参数单位和哈希。模板决定动作与依赖，参数实例决定温度、时间、质量等；LLM 不为每次实验任意改图。
2. **任务与作业**：UniLabOS 是工作流状态来源。复用 `@openlab/protocol` 读取；SSE 只通知重读，不能将事件当作完整状态。
3. **实际提交**：浏览器请求平台执行服务；平台使用真正的 MCP ClientSession 调用已发现的 UniLabOS 工具，保存工具输入输出及 task/job ID。不能在前端伪造 succeeded，不能直接用 UI 本地动画代替提交。
4. **轨迹执行**：新驱动提交命令后等待结果。浏览器仅在最后一帧和终态检查完成后 ACK；服务器验证身份、序号、对象终态，持久化后才让驱动返回。
5. **执行方式**：页面区分“网页轨迹仿真”“Isaac 实时仿真”“历史回放”。Isaac 模式由实际物理 worker 完成作业，网页观察状态；不能拿网页 ACK 替代物理结果。
6. **多标签与断线**：每个运行仅一个有效执行会话，带租约及 epoch；其他标签是观察者。刷新、重复 ACK、过期 ACK 不重复动作或推进下一步。执行器离线后暂停/超时失败，进入明确恢复流程。

命令/回执最少携带：`run_id`、`task_uuid`、`node_uuid`、`job_uuid`、`operation_id`、`command_id`、`attempt`、`lease_epoch`、`template_version`、`scene_hash`、`trajectory_hash`、对象与目标位、起止状态、仿真时间、实际时间及错误。命名在 P1 定稿，不能仅凭一个 `success=true` 作为跨系统完成依据。
