# Agent failure modes and implemented guards

This table turns the BYZSO/LLZO run audit into executable policy. It distinguishes
scientific uncertainty from orchestration failure: a guard can prove that a tool
ran correctly, but it cannot turn a model-predicted precursor set into a validated
synthesis route.

| Observed failure | Implemented guard | Verification |
|---|---|---|
| The 2015--2020 extraction subset was mistaken for the full local archive | Corpus status reports the selected roots, engine, package mode, and schema. The example environment now calls the private source the complete prepared archive and does not encode year roots. | `tools/check.sh --corpus` |
| Markdown-only search could not read the real Parquet store | DuckDB search and bounded reads share the MCP output schema with the Markdown backend. | Offline Parquet search/read test |
| A public package still depended on the private DOI SQLite and ingest shards | `goai-compact-parquet-v1` resolves DOI directly from its own Parquet rows. Private index variables are optional only for compact packages and must otherwise be configured as a pair. | Repository demo and compact-export DOI tests |
| An exporter could accidentally carry unrelated private files | Export is allow-list-only, requires an explicit redistributable flag and license, rejects non-empty destinations, accepts only UTF-8 text for compact output, and never writes private source paths into the public manifest. | Allow-list/export regression test |
| The validation command used system Python and reported missing dependencies | `tools/check.sh` always executes `.venv/bin/python`; `tools/preflight.py` rejects any other prefix and checks server imports and optional corpus/model assets. | `tools/check.sh --servers` |
| The retro MCP and model dependencies were installed in different environments | `install.sh --retro` installs MCP and model dependencies into the same `.venv`, then runs the model asset/dependency/hash preflight. | `tools/check.sh --retro` |
| Long agents waited until the final response to write results | Declared-artifact tasks receive a runner protocol requiring early, incremental writes. Fresh/non-empty artifacts remain mandatory. | Runner artifact tests |
| A retry read its own growing JSONL and recursively amplified context | The runner injects the exact active log directory as forbidden input; only an explicitly named, closed prior run may be inspected. The repository agent rules repeat this boundary. | Prompt protocol plus trace audit |
| A report or reference guard completed its files but hung during shutdown | Process status and artifact status are separate: `.process_exit=124` is preserved, while fresh declared artifacts can yield `WARN_ARTIFACT_PASS_AFTER_TIMEOUT`. Set `RUNNER_TIMEOUT_ARTIFACT_POLICY=fail` for strict mode. | Live timeout-after-write test |
| A consumer started before its evidence producer finished | TSV column 4 declares dependencies. Dependencies must reference earlier rows; failure blocks the consumer without launching it. | Live ordering/block test |
| The test host had no TeX, so writers "rendered" the manuscript with groff/Ghostscript and HTML→HeadlessChrome; the ledger recorded `draft_complete` PASS while the PDF had no abstract block, no numbered headings, broken equations/tables, black citations and system fonts | `tools/check.sh --tex` preflights engines and every template package before writing may start; `tools/pdf_guard.py` verifies the delivered PDF's Producer/Creator is a TeX engine, embedded fonts are the template family, the PDF is newer than its sources, page 1 carries an Abstract/摘要 block and the body has numbered top-level headings. Missing TeX is fail-closed: `draft_complete` = FAIL, deliver `main.tex` + bib + figures and state "PDF not compiled"; fallback renderers are banned (AGENTS rule 15). | `tools/check.sh --tex`; `pdf_guard` regression tests (real xelatex sample passes, Chrome-rendered PDF fails on five counts) |
| Bibliography titles lowercased into fragments (`li 7 la 3 zr 2 o 12`), DOI+URL duplicated on every entry, bare `&` aborting the build, and unbreakable `phase/density/transport` slashes producing 25–37 pt overfull lines; a stray `$` and a missing `\\` in a table row were silently swallowed by the browser render and only surfaced under TeX | `tools/bib_polish.py` (drop url when doi exists, brace-protect formulas/acronyms/element prefixes, merge spaced formulas, escape `&`) and `tools/tex_polish.py` (breakable `\slash` in prose with command arguments masked, `\bibliography` path normalization, SVG-include detection); `scripts/build_tex.sh` does a clean xelatex→bibtex→xelatex×2 build and ends with `pdf_guard`; `scripts/package_submission.sh` runs `pdf_guard` on every manuscript PDF before zipping | `bib_polish`/`tex_polish` regression tests; four submission manuscripts rebuilt to 0 errors |
| Hundreds of library keys were dumped into one "grouped citation" paragraph to inflate the integration rate, producing a wall of citation numbers | Writer rule: every claim carries only the citations that support it; a single `\cite` holds ≤ 5 keys; orphan entries are placed, justified in a table/appendix, or removed via lit_search review — never dumped. | Reviewer citation-context check; bib_guard orphan report |
| A bare-topic cold start on a *synthesis conditions* topic recorded `ideas_reviewed: WARN (skipped)`, treating ordinary oxide/silicate solid-state and flux routes as a "hazardous protocol" that needs a human safety stop; the conclusion then refused to recommend any precursor, temperature or route, so the deliverable lacked the required direction→process+precursor table | `loopctl` classifies the topic mechanically (`SYNTHESIS_TOPIC_RE` over the ledger topic and `scope.md`); for such topics `gate ideas_reviewed` rejects skip-style WARN, requires a `predict_precursor_routes` audit event recorded after ledger creation (the environment preflight sample does not count) plus an `ideas/` file naming both a process route and precursors, `gate draft_complete` rejects a manuscript that never mentions precursors, and `check-done` re-verifies all three. The orchestrator/idea-forge skills now define the hazard classes exhaustively (energetic materials, highly toxic gases, >10 MPa, bio/radioactive/controlled) and withhold only routes in those classes; writer and reviewer treat refusal-style conclusions as a major issue | `tests/test_offline.py::test_loopctl_synthesis_topic_cannot_skip_ideas_lane`, `::test_loopctl_non_synthesis_topic_may_skip_ideas`, `::test_skills_make_ideas_lane_mandatory_for_synthesis_topics` |
| `bib_polish` protects chemical formulas in titles (`{Ba}$_5$Y$_{12}$…`) but the citation audit normalised them to `ba 5 y 12` and compared against the publisher's `ba5y12`, so 12 genuine entries were flagged FIX; publisher metadata can also split subscripts as `Ba 2 Gd 2 (Si 4 O 13 )` | `server/core/textnorm.norm_title` strips TeX commands, math shifts, braces and HTML tags before normalising; `bibtex.title_similarity` takes the max of spaced and space-free comparison | `tests/test_offline.py::test_norm_title_strips_tex_and_html_markup_and_tolerates_spaced_formulas` |
| `scripts/reproduce_core.sh` used `shopt -s globstar` (bash ≥ 4) so the verification phase aborted on macOS's bash 3.2; it also ran `academic_language_guard` over the whole `drafts/` directory (flagging planning notes such as `blueprint.md`) and demanded an all-PASS citation audit although the refcheck gate legitimately allows FIX, so a run that had completed correctly was reported as failed | Recursive traces are collected with `find`; the guard scope matches the skills (`drafts/sections` + `main.tex`); the audit check uses the server gate semantics (MISMATCH/UNVERIFIED/ERROR must be zero) and records PASS/FIX counts in the receipt | `tests/test_offline.py::test_shell_scripts_stay_bash32_compatible`, `::test_reproduce_core_matches_protocol_guard_scope_and_audit_semantics`; `bash scripts/reproduce_core.sh --verify-only --workdir <ws>` on macOS |
| The writer declared synthesis parameters "not reported" for papers of which only the abstract or SI had been read (two open-access full texts did report crucible, atmosphere and temperatures; one paywalled experimental section was called "undisclosed") | `papers.jsonl` records carry an `access` level (`fulltext`/`si`/`abstract`/`metadata`) written by lit-search after exhausting legal full-text routes; the writer may write "not reported" only for `fulltext` entries and must otherwise write "full text not obtained"; the reviewer checks every such claim against the access level and opens a major issue on mismatch | `tests/test_offline.py::test_skills_make_ideas_lane_mandatory_for_synthesis_topics` (rule-presence tripwire); adversarial review round 1 of the 2026-09-05 run (`state/review_round1.md`, issue I2) |
| Resuming the 2026-09-05 run under the new ideas-lane rule, `tools/parallel_run.sh` aborted at launch on macOS `/bin/bash` 3.2: with `set -u` an empty dependency/artifact column expands `"${arr[@]}"` as an unbound variable, so the whole parallel batch died before any sub-agent started | All array expansions that may be empty use the bash-3.2-safe `${arr[@]+"${arr[@]}"}` idiom (`_json_list`, dependency and artifact loops, the launched-task summary) | `tests/test_offline.py::test_parallel_run_json_helpers_survive_empty_lists_under_bash32_set_u` (executes the helpers under `/bin/bash -u`) |
| Figures looked like a smear of tiny text in the PDF: canvases of 1500–1680 px with 17–20 px labels were placed at `\textwidth` (451 pt), i.e. 5.1–5.6 pt in print, yet the render lint passed them because its floor (4.5 pt error / 5.2 pt warning) was the publisher's absolute minimum for tick labels | `figspec.lint` converts to print points against a per-figure target width (`canvas.target_width_mm`/`target_width_pt`, default 451 pt A4 single column) and rejects body text below 6.5 pt (warns below 7.5 pt, title below 9 pt); the error names the maximum canvas width or minimum font that would pass; figure-studio's size table is re-based on a 1000 px canvas ("canvas width ≤ smallest body font × 60") | `tests/test_offline.py::test_figspec_lint_font_floor` (the three real figspecs of the 2026-09-05 run now fail with 22–30 errors each) |
| Seven-column portrait tables (`P{0.12\textwidth}` × 7) wrapped Chinese cells to 4–5 characters per line and stacked two such tables per page — the reader's impression of a "messy layout" | `tex_guard` rule 10 blocks portrait `tabular/longtable` with ≥ 6 columns and a cell longer than 40 units (CJK counts 2) or ≥ 8 columns; tables inside `landscape`/`sidewaystable` are exempt; both templates load `pdflscape` + `longtable`, preflight checks them; the writer skill caps portrait tables at 5 columns, fixes a five-column layout for condition–result tables and moves meta-information out of tables | `tests/test_offline.py::test_tex_guard_blocks_dense_portrait_tables`; the run's 9 condition tables are all flagged |
| A Chinese topic line made the orchestrator auto-select Chinese delivery although the user wanted an English, top-venue-style survey | Delivery language defaults to English; only an explicit user request yields Chinese. `loopctl gate scope_confirmed` requires the language declaration in `--detail` and rejects a Chinese declaration without "用户要求" evidence; `gate draft_complete` compares the manuscript's CJK ratio against the `scope.md` declaration and rejects drift | `tests/test_offline.py::test_loopctl_delivery_language_defaults_to_english_and_blocks_drift` |
| `parallel_run.sh` parsed the sub-agent model from `RUNNER_ARGS` with a GNU-only sed expression (`t; s/…/`); BSD sed on macOS rejected it, every batch's `RUN_INFO.json` recorded `model: ""`, and when the pinned model became unavailable mid-run (HTTP 400 for gpt-5.6-sol; the orchestrator switched sub-agents to gpt-5.5) the audit could not attribute which model wrote what | Two independent sed expressions (POSIX classes, no labels) cover `-m`, `--model`, `--model=`, `-c model=…`; the reproduction receipt aggregates actual models per batch into `sub_agent_models` so a mid-run substitution is visible next to the pinned `model` | `tests/test_offline.py::test_parallel_run_model_parsing_is_bsd_sed_safe` (executes the parser under `/bin/bash` for five argument shapes) |
| A conference abstract (no DOI, not indexed) could only pass the citation gate as UNVERIFIED-free if its entry was mangled into the whole abstract volume's title and DOI — which an earlier round did, and two audits accepted it, so readers could not locate the cited abstract (round-5 review, I14) | `goai-refcheck` gained a `MANUAL` verdict for grey literature: the entry keeps its own author/title/booktitle/year, an official `url`, a `note`, and `verified = {manual: <who> <date> <locator>}`; entries with a DOI, without an official URL, of journal type, or with a malformed marker stay UNVERIFIED. The gate allows MANUAL (reported separately); the ref-guard skill forbids satisfying the checker with volume-level DOIs | `tests/test_offline.py::test_refcheck_manual_verdict_for_grey_literature` |
| 79 of 80 journal references had no volume/issue/pages, ~18 titles printed formulas without subscripts, surnames and two titles were ALL CAPS, `x-ray`/`rietveld` lowercase (round-5 review, I20/I35) | New `tools/bib_enrich.py` fills volume/number/pages from Crossref by DOI (fill-only) and unifies years to the publication year; `bib_polish` subscripts chemical formulas (incl. hyphenated system names inside braces), protects `{X}-ray` and proper nouns, and re-cases ALL-CAPS surnames/titles while preserving math and braced segments | `tests/test_offline.py::test_bib_polish_fixes_hygiene_without_touching_meaning` |
